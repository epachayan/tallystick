## Result 4 — B4 is a negative result: proving membership costs more than telling

B4 replaces content disclosure with Merkle membership queries over committed sets. The
adjudicator never sees the scope or the execution record; it asks "is action *a* in the
committed scope?" and gets a proof.

It recovers every semantic class that died under B2 — M1, M2, M6, M11 — at full accuracy:
250 correct blame, 0 false accusation, 0 missed, matching B3.

**And it costs more than simply revealing everything.**

| scope | B3 full record | B4 exhaustive queries | ratio |
|---|---|---|---|
| 2 | 388 B | 390 B | 1.01× |
| 8 | 539 B | 1,013 B | 1.88× |
| 32 | 1,153 B | 4,506 B | 3.91× |
| 64 | 1,981 B | 10,493 B | **5.30×** |

The arithmetic is unforgiving. One membership proof is ⌈log₂ n⌉ sibling hashes at 32 bytes
each, plus the queried label. The item itself is roughly 20 bytes. So proving membership of
an item costs several times what showing the item costs — and if you query every item, you
have disclosed the whole set anyway *plus* the proof overhead.

**Exhaustive adjudication over commitments is strictly worse than full disclosure, and the
gap widens with record size.** This is worth stating plainly because "use commitments and
selective disclosure" is the reflexive recommendation in this space, and applied
exhaustively it is counterproductive.

## Result 5 — The disclosure benefit is governed by dispute breadth, not record size

B4's problem is not commitments. It is that it audits rather than adjudicates.

Under the offline/optimistic adjudicator we adopted, a dispute is *raised about something
specific*: the principal says "you did X and were not permitted to"; the executor says "you
granted Y and now deny it". The complainant names the item. The adjudicator issues a
**bounded** number of queries, not a sweep.

B5 is B4 with the query set bounded by the dispute:

| scope | B3 full record | B5 dispute-driven | ratio |
|---|---|---|---|
| 2 | 388 B | 297 B | 0.77× |
| 4 | 439 B | 315 B | 0.72× |
| 8 | 539 B | 336 B | 0.62× |
| 16 | 739 B | 358 B | 0.48× |
| 32 | 1,153 B | 379 B | 0.33× |
| 64 | 1,981 B | 403 B | **0.20×** |

Accuracy is identical to B3 at every size: 150/0/0 across the sweep.

So the shape of the answer is:

> **Disclosure cost under commitment-based adjudication scales with the number of disputed
> items, not the size of the record. B3 grows O(n). B4 grows worse than O(n) — O(n log n).
> B5 grows O(log n).**

The design principle that falls out is short enough to be actionable:

> **Bound the queries, or don't bother with commitments.**

At scope 64 the same accuracy is available at one fifth the disclosure — and the advantage
compounds, because B5's curve is nearly flat (297 → 403 bytes across a 32× increase in
record size) while full-record disclosure grows linearly.

This also revises Result 2 from Experiment 01. The semantic/integrity boundary is real, but
it is not a *hard* boundary: semantic adjudication is recoverable under limited disclosure
provided the dispute is narrow. What B2 actually demonstrated was the cost of adjudicating
semantics with *no* query mechanism at all.

## Result 6 — The validator works, and would have saved the earlier debugging

`validate.py` checks scenario self-consistency: a record flagged as altered must actually
differ from ground truth; a party marked dishonest must assert something false; a party
marked honest must not; unadjudicable scenarios must genuinely lack a settling artifact.

Current corpus: **325 scenarios, 0 violations.**

Confirmed against a synthesised instance of the exact v0.1 M4 bug — record flagged altered
while content matched ground truth — which it catches immediately. That bug previously took
score archaeology to find.

## What this changes about the project

The earlier recommendation was Outcome C — write the mapping paper, drop the construction.
That still holds for the *primary* output, but Results 4 and 5 add something the mapping
paper did not have: **a measured design principle with a counter-intuitive negative result
attached.** That is publishable content in its own right, and it came from three days of
work rather than a year.

The honest framing of what B5 is: not a new primitive. Merkle commitments and membership
proofs are decades old, and bounding queries to the dispute is what the optimistic
adjudicator model implies anyway. The contribution is **measuring that the two must be
combined**, and showing that the obvious application — commitments plus exhaustive
verification — is worse than doing nothing clever at all.

## Caveats, unchanged and new

- Still no cryptography implemented. Proof sizes are analytic (⌈log₂ n⌉ × 32 B), not measured
  from a real Merkle implementation. A real one would add framing overhead and should be
  measured before publication.
- Disclosure is serialized bytes reaching the adjudicator — a proxy, not an
  information-theoretic measure. B5 leaks *which* item was disputed; that leakage is not
  captured by a byte count and may matter more than the bytes.
- **New:** B5 assumes the complainant names the disputed item honestly. A complainant who
  names the wrong item forces additional queries, and an adversarial complainant could use
  query selection as an oracle to probe the committed set. Neither is modelled. This is the
  most obvious attack on B5 and it should be an M-class.
- Two parties only. M-class taxonomy still needs reconciling against the authoritative list.

## Addendum, 11 August 2026 — exhaustive querying buys nothing

Recorded late, and only because a pruning audit flagged `B4_scope_predicates` as
cited by no live claim. It was not redundant; it was carrying a result nobody
had written down.

| protocol | query strategy | disclosure | classes solved |
|---|---|---|---|
| B4 | exhaustive over every value either party named | 383 B | same as B5 |
| B5 | bounded by the explicit complaint | 284 B | same as B4 |

**Identical resolution, 35% more disclosure.** Widening the query set beyond
what the complaint actually contests costs bytes and buys nothing, because a
value neither party mentioned cannot be the subject of a dispute the
adjudicator was asked to settle.

This is the negative result that justifies the dispute-bounded design, and it
had been sitting unstated in the results table since the selective-disclosure
line was built. `make check` now fails if any protocol is cited by neither a
claim nor a registered open question, so an unstated result of this kind cannot
hide again.
